# sd-studio — ローカル画像生成（Stable Diffusion / ComfyUI）

Mac mini M4 Pro（24GB, MPS）でローカル完結する画像生成環境。ネットにも課金にも依存しない。

## 構成
| 場所 | 中身 |
|---|---|
| `~/ComfyUI` | ComfyUI本体・venv（Python 3.12）・モデル。サードパーティなのでgit管理外 |
| `dev/sd-studio`（ここ） | 起動スクリプト・生成CLI・プロンプト集・出力。git管理 |

## 使い方
```bash
# 1. サーバ起動（起動しっぱなしにする。ブラウザGUIは http://127.0.0.1:8188）
dev/sd-studio/bin/start.sh

# 2. 別ターミナル or Claude から一括生成
python3 dev/sd-studio/gen.py "1girl, sake brewery, kimono" -n 4
python3 dev/sd-studio/gen.py "japanese sake bottle on wooden counter" -m photo
# LoRA を噛ませる（~/ComfyUI/models/loras のファイル名。例: ドット絵用 pixel-art-xl）
python3 dev/sd-studio/gen.py "pixel art, wolf boss, plain magenta background" --raw --lora pixel-art-xl.safetensors --lora-w 1.0
```

出力は `out/` に落ちる（gitignore済み）。

## GUIの使い方（ComfyUI）
既定テンプレートはうちに無いモデルを読もうとしてエラーになる。**左の「ワークフロー」（Wキー）から番号付きの4本のどれかを開く**こと。プロンプト工房のモデル選択と名前が対応している。

| ワークフロー | 中身 | 工房のモデル |
|---|---|---|
| `1_イラスト` | animagine + イラスト用ネガティブ | イラスト |
| `2_写実` | juggernautXL + 写実用ネガティブ | 写実 |
| `3_動画` | LTXV テキスト→動画 | 動画 |
| `4_静止画から動画` | LTXV 画像→動画（アニメ向き） | 動画 |
| `5_手本の絵柄に寄せる` | animagine ＋ IP-Adapter（手本の画像で絵柄を寄せる・個人利用に限る。使い方は画面左上のメモ） | イラスト |
| `6_人物とポーズを組み合わせる` | animagine ＋ IP-Adapter（Aの人物）＋ DWPose→ControlNet（Bのポーズ）。顔の手本は既定で外してある（使い方は画面左上のメモ） | イラスト |

**モデルごとにネガティブが違うので、1本を使い回さず用途で開き分ける**（写実にイラスト用ネガティブを入れると、juggernautを写真に留める `cartoon, anime, 3d render` が抜けてしまう）。出力ファイル名も用途別（`illust_` / `photo_` / `video_`）。

ワークフローの実体は `workflows/build.py` で生成する。ネガティブは `genres/_common.py` から引いているので、工房と同じ定義になる。直したら `python3 workflows/build.py` で作り直す。

触るのは2か所だけ：
| 場所 | 何 |
|---|---|
| 上のテキスト欄（プロンプト） | 描きたいもの。プロンプト工房で組んだものを貼る |
| KSampler の `シード` | `randomize` なら毎回違う絵。固定すると同じ絵が再現できる |

下のテキスト欄（ネガティブ）とサイズは、慣れるまで触らなくていい。

## モデル
| プリセット | ckpt | 用途 |
|---|---|---|
| `illust`（既定） | animagine-xl-4.0-opt | アニメ・イラスト。カード絵、キャラ、ゲーム素材（2026-10-10に無印から改良版へ。無印は削除済み。過去の記録を再現するときは取り直して `--ckpt` で指定） |
| `photo` | juggernautXL-v9 | 写実。酒瓶・料理・資料スライド用 |
| （動画） | ltxv-2b-0.9.8-distilled ＋ t5xxl_fp16 | 下記「動画」参照。VAEはチェックポイント同梱 |

VAE は `sdxl_vae.safetensors`（fp16-fix）を共通で使う。

## 動画（LTXV）
ワークフロー `3_動画` を開く（Wキー → 一覧から選ぶ）。出力は `.webm`（vp9）で `~/ComfyUI/output/` に落ちる。

| 実測（M4 Pro 24GB） | 所要 |
|---|---|
| 512×320 / 25フレーム（1.0秒） | 81秒 |
| 768×512 / 97フレーム（3.9秒） | 113秒 |

どちらも全編で構図が安定し、破綻なし（フレームを抜いて目視確認済み）。

**設定の決まりごと**（LTXV公式の制約）
- 解像度は **32の倍数**、フレーム数は **8の倍数+1**（25, 33, 97 など）
- 720×1280未満・257フレーム未満に収める
- distilled版なので **steps=8 / cfg=1.0**。cfgを上げても良くならない

**Wanは使わない**。ComfyUI Issue #15793 に、この機体と同一構成（Mac mini M4 Pro 24GB）で映像が溶ける報告がある。M3 Proでは出ずMPSカーネルのシリコン世代依存で、回避策なし。

**注意**: 動画関連ノードは209個あるが、うち87個は ByteDance / Grok / Gemini / Runway 等の**外部API課金ノード**。ローカル生成は122個の方。うっかり課金ノードを繋がないこと。

### アニメ動画
2つの道があり、性質が違う。どちらも所要は約2分（768×512）。

| 経路 | ワークフロー | 絵柄 | 安定性 |
|---|---|---|---|
| テキスト→動画 | `3_動画` にアニメ指示を書く | フラットな海外カートゥーン寄り | 97フレームでも崩れない |
| 静止画→動画 | `4_静止画から動画` | **日本のアニメ調が保たれる**（静止画側が絵柄を決めるため） | 尺に依存。17Fなら元絵を保つ、33Fで衣装が変わり始め、97Fで破綻 |

日本のアニメ絵が欲しいなら後者。手順は「animagineで1枚描く → `~/ComfyUI/input/` に置く → LoadImageで選ぶ → 実行」。
**既定は17フレーム（0.7秒）**。尺を伸ばすほど人物が別人に変形していく（上の表）。

## プロンプト工房（日本語でプロンプトを組む）
**ジャンルごとに別ポート・別プロセス**で動く。同時に立ち上げてよい。

**入口はこれ1本**。全ジャンルを起動して、カード一覧のページを開く（動いているものはそのまま）。
```bash
dev/sd-studio/bin/studios.sh
```
止めるときは `bin/studios.sh stop`。

1つだけ立てたいときは個別に：
```bash
dev/sd-studio/bin/prompt_studio.sh --list       # 一覧
dev/sd-studio/bin/prompt_studio.sh fantasy      # ファンタジー
```

| ジャンル | ポート | 語彙 |
|---|---|---|
| `brewing` 醸造・日本酒 | 8511 | 130 |
| `fantasy` ファンタジー | 8512 | 134 |
| `landscape` 風景・自然 | 8513 | 129 |
| `food` 料理・食べもの | 8514 | 124 |
| `portrait` 人物・ポートレート | 8515 | 150 |

入口ページ `studios.html` は `bin/studios.sh` が毎回その場で組み立てる（ジャンルを足せば自動で並ぶ。手で編集しない）。

### 工房を1つ足す（3手）
```bash
cp genres/_template.py genres/<名前>.py     # 1. ひな形をコピー
#    TITLE / PORT / VOCAB を書き換える（必須はこの3つだけ）
bin/prompt_studio.sh <名前>                 # 2. 起動して触る
python3 web/build.py                        # 3. 公開版に載せるならビルド（PUBLISH=True のとき）
```
`ALWAYS`（常時表示）と `ROLL_CHANCE`（おまかせ確率）は**省略すると自動で決まる**（先頭2カテゴリが常時表示・確率1.0、残りは0.6）。カメラの動き・品質タグ・ネガティブは `genres/_common.py` から自動で入る。コードは全ジャンル共通の1本。

- **`PUBLISH = False`** にすると公開版（`docs/index.html`）に載らない。テスト用の工房はこれを使う
- ファイル名が `_` で始まるものは工房として読み込まれない（`_template.py` `_common.py`）
- ポートは他と重ならない番号にする（既存 8511〜8515、テスト 8520）
- 一覧は `bin/prompt_studio.sh --list`

### 表から取り込む
スプレッドシートの表（カテゴリ名の行 → `No. / English Keyword / 日本語訳` の見出し → 中身、の繰り返し）をCSV/TSVで書き出して読ませる。
```bash
python3 web/import_table.py 表.tsv --name mygenre --title "私の工房" --port 8521 --icon 📋
```
- 空欄の行・番号だけの行は飛ばす。同じ日本語ラベルは1回だけ採る
- 区切りはタブ/カンマを自動判別。引用符つき・BOMつきでも読む
- **写実用の語（3つ組の3番目）は表に無いので `None` になる**。写実・動画モードでは英語キーワードがそのまま使われるので、必要なら生成後に手で足す
- 既定で `PUBLISH = False`（公開版に載らない）。載せるなら `--publish`
日本語ラベルを選ぶと英語プロンプトが組み上がる。**モデルで出力が変わる**——イラスト側はDanbooruタグ列、写実側と動画側は自然な英文。ネガティブも連動する。

モデルは3つ：`イラスト（animagine）` / `写実（juggernautXL）` / `動画（LTXV）`。
**動画のときだけ「主役の動き」「カメラの動き」の2カテゴリが出る**。常時表示に入るのは「主役の動き」だけ——カメラは指定しなくてもLTXVが勝手に少し動くので、二次的な選択として「もっと選ぶ」の中に置いている。カメラ指示が実際に効くことは実機で確認済み——「ゆっくり寄る」で被写体に寄り、「ゆっくり右へ振る」で横に流れる。

- 常時見えるのは「主役」「場所」（動画ではさらに「主役の動き」）。残りは「もっと選ぶ」の中（見出しに選択済みラベルが並ぶ）
- **「文章で書く」**に日本語の文を入れて **Enter → 「言葉を拾う」** で、語彙を自動で拾って選択欄に入れる。拾った結果はそのまま直せる
  - 辞書照合だけで動く（外部モデルなし＝即座・確実）。漢字とカタカナの塊で突き合わせ、ひらがなの接続部分は見ない（「差し込む」が「回り込む」に当たるのを防ぐ）
  - **取りこぼしは出る**。誤った語を混ぜるより取りこぼす側に倒してある（足すのは簡単、間違いに気づかない方が危ない）
  - 拾える率を上げる手は2つある。**言い換え**を足す（`ALIASES`）と、**語彙そのもの**を足す。前者は出力を一切変えずに拾える率だけ上がる
  - 反映されなかった言葉は画面に出る。**2種類あり、打つ手が違う**
    - 「**◯◯ は語彙にあるが選ばれなかった**」＝同じ枠で別の候補が勝った。選択欄で直す。放置すると「男性」と書いて女性が出るような黙った取り違えになる
    - 「**語彙に無い言葉：◯◯**」＝そもそも持っていない。要るなら `genres/<ジャンル>.py` に足す
  - **入力した文章は保存しない**（画面に出すだけ）

### 語彙の育て方
公開されている日英対訳データ（Danbooruタグの訳など）は調べたが**取り込まない**。アニメ絵タグ体系に偏っていて数万語あり、混ぜると画風が引っ張られ、おまかせが雑音だらけになる。**写実・動画用の自然な英文の対訳は、そもそも公開データに存在しない**（2026-09-11 調査）。

増やすときは、**使っていて上の2つの表示に出た言葉から**足す。先回りして大きな辞書を作らない。
  - 例文はジャンルごとに用意してある（入力欄の薄い文字）
- 「🎲 おまかせ」はカテゴリごとに採用確率を変えて抽選する（主役と場所は必ず、季節は時々）。主役に「人物なし（風景）」「酒器だけ」を引いたときは、服装・しぐさを付けず、動きも人物不要のものだけから選ぶ（矛盾したプロンプトを作らないため）
- **生成はしない**。出た文字列をComfyUIのプロンプト欄に貼る
- 語彙の追加・修正は `genres/<ジャンル>.py`。日本語・イラスト用タグ・写実用の語の3つ組で書く
- **`ALIASES`（任意）** = `{正式ラベル: (言い換え, ...)}`。照合にだけ使い、プロンプトには出ない。「メガネ→眼鏡の知的な女性」「杉林→針葉樹の林」のように、**語彙を増やさず拾える率だけ上げたいとき**に使う
- **日本語ラベルと英語タグの性別・人数を一致させること**。「〜な人物」と書いて `1girl` を吐くと嘘になる
- 語彙どうしが同じ語を含んでも、組み立て時に重複を落とす（風景の多くが `scenery` を持つため。重ねるとその語の重みが不当に上がる）

Streamlit は jbsj の venv を間借りしている（蔵元司令室と同じ方式）。ポート8511（8510は蔵元司令室）。

### 静止画から動画にするときのプロンプト（実測で確かめた）
静止画用とは別物。**タグ列ではなく自然な英文**で、かつ「絵の内容」と「動き」を**両方**書く。

| 書き方 | 結果 |
|---|---|
| 絵の内容だけ | 動くが、動きの向きが定まらない |
| **動きだけ** | **衣装が元絵から離れやすい**（描写が無いと絵を保てない） |
| **絵の内容＋動き**（推奨） | 動きが滑らかで向きが定まる。既定プロンプトはこの形 |
| 空 | ほぼ静止画のまま（総変化量が他の1/3以下） |

書く順番は「何が写っているか → 何が動くか → カメラがどう動くか」。プロンプト工房の「動画」モードがこの順で組む。

**工房の動画モードは2本同時に出す**——「動画用」と「元になる静止画用」。同じ選択から作るので情景が揃う。揃えた場合とズラした場合を実測したところ、揃えた方が元絵から離れにくく（末尾と元絵の差 25.4 対 30.3）、動きも滑らかだった（1コマ変化 4.0 対 4.9）。ただし1回の試行なので参考値。

`4_静止画から動画` の使い方：工房で選ぶ → ②を `1_イラスト` に貼って1枚描く → その絵を `4` に渡す → ①を `4` のプロンプト欄に貼る → 実行。

**尺と忠実度はトレードオフ**（同じ絵・同じシードで実測）
| 尺 | 元絵の保たれ方 |
|---|---|
| 17コマ（0.7秒・既定） | 衣装・人物とも保たれる |
| 33コマ（1.3秒） | 帯の色が変わり始め、手が怪しくなる |
| 97コマ（3.9秒） | 明確に破綻（腕が壊れる） |

`LTXV画像を動画に` の `strength` は**既定の1.0が上限**なので、画像を保つ力をこれ以上上げる手はない。長くしたいときは短いクリップを複数作って繋ぐ方が確実（未検証）。

**https://y-kanno-sakenote.github.io/sd-studio/**

## 外部ブラウザから使う（iPhone・MacBook Air）
Tailscale に繋いだ自分の端末だけから使える。**公開はしない**。

```bash
dev/sd-studio/bin/studios.sh          # 工房5つ（起動時にTailscaleのURLを表示）
dev/sd-studio/bin/start.sh --remote   # ComfyUI も外から使うとき
```

| | localhost | Tailscale（自分の端末） | 同じWi-Fiの他人 |
|---|---|---|---|
| プロンプト工房 8511-8515 | ○ | ○ | ○ |
| ComfyUI 8188（既定） | ○ | × | × |
| ComfyUI 8188（`--remote`） | ○ | ○ | **×** |

ComfyUI は `--listen 127.0.0.1,<TailscaleのIP>` で**その2つだけ**に開く。同じWi-Fiに繋いだ他人からは見えない。入口ページ `studios.html` のリンクも Tailscale のIPになるので、iPhone に送ればそのまま使える。

**ComfyUI を公開してはいけない**。認証が無く、ファイルの読み書きとカスタムノードによるコード実行ができる。ポート開放・ngrok・Cloudflare Tunnel などで外に出さないこと。プロンプト工房の方は固定の語彙から文字列を組むだけなので危険は小さい。

止めるときは `bin/studios.sh stop` / `bin/start.sh stop`。

## 手本の絵柄に寄せる（IP-Adapter・個人利用に限る）
気に入ったイラストを手本にして、絵柄（塗り・色づかい・線の雰囲気）を寄せて描かせる。2026-10-17 導入。ComfyUI の画面（スマホからも可）ではワークフロー `5_手本の絵柄に寄せる` を開く

```bash
python3 dev/sd-studio/gen.py "a bottle of sake on a wooden table, no humans" --ref ~/Desktop/お手本.png
python3 dev/sd-studio/gen.py "..." --ref お手本.png --ref-mode strong --ref-w 0.5
```
| `--ref-mode` | 中身 |
|---|---|
| `style`（既定） | 絵柄だけ寄せる。手本の構図や中身は写さない |
| `strong` | 絵柄を強く。強さ0.8だと手本の中身まで漏れた → `--ref-w 0.5` 前後から |
| `all` | 絵柄も中身も寄せる。手本がほぼそのまま出るので使いどころ注意 |

- `--ref-w` は効きの強さ（既定0.8）。手本を使うと1枚あたり約1.4〜1.5倍の時間がかかる
- 中身：拡張 `~/ComfyUI/custom_nodes/ComfyUI_IPAdapter_plus`（cubiq、2025-04以降更新なし）＋ `models/ipadapter/ip-adapter-plus_sdxl_vit-h.safetensors` ＋ `models/clip_vision/CLIP-ViT-H-14-laion2B-s32B-b79K.safetensors`（どちらも Hugging Face h94/IP-Adapter）
- **約束**：生成物は手元だけで使う（公開・販売・SNSに出さない）／特定の作家名をプロンプトに入れない／既存のキャラクターを再現しない／手本の画像とプロンプトは記録にもgitにも残さない。手本は毎回別名で ComfyUI に上げ、生成が終わったら `~/ComfyUI/input` から消える

## Aの人物 × Bのポーズ（イラスト・個人利用に限る）
2026-10-19 導入。Bの画像から姿勢の骨組み（DWPose）を取り出して ControlNet で描かせ、Aの人物は IP-Adapter で寄せる。

```bash
python3 dev/sd-studio/gen.py "1girl, short red hair, green eyes, white haori, navy hakama, waving, full body" \
  --ref A.png --ref-mode all --ref-w 0.45 --pose B.png -s 832x1216
python3 dev/sd-studio/gen.py "..." --pose B.png --draft     # 下書き（約0.6倍の大きさで速く。良いものだけ本番の大きさで）
```
- **実測（2026-10-19）**：`--ref A --ref-mode all --ref-w 0.45 --pose B --pose-w 0.75` で、Aの髪・服の飾りを保ったままBの姿勢（手を振る・腰に手）が出た。1枚約1.5〜2分（下書きは約30秒）
- **顔の手本 `--face`（顔のあたりの切り抜き）**：イラストでは 0.5〜0.6 で画面が白っぽく荒れた。0.3 でも荒れることがある → **まず顔なしで描き、足りないときだけ足す**（背景の白っぽさは `--ref-mode all` の影響もありうる。未検証）
- 文（プロンプト）にもAの特徴とBのポーズを書くと効きがよい
- 手本を使う生成の前に、Ollama のモデルを自動で下ろしてメモリを空ける（`--keep-ollama` で無効）
- 中身：拡張 `comfyui_controlnet_aux`（Python部品は本体の版を固定して導入。導入前の一覧は `~/ComfyUI/pip_freeze_before_controlnet_aux_20261019.txt`）＋ `models/controlnet/controlnet-openpose-sdxl-xinsir.safetensors`（xinsir）＋ `models/ipadapter/ip-adapter-plus-face_sdxl_vit-h.safetensors`（h94）。DWPose のモデルは初回の実行時に自動で入る
- 約束は「手本の絵柄に寄せる」と同じ。Aに使うのは自分のキャラか了承を得た人物だけ。既存のキャラクターは再現しない

## 使い終わったらメモリを空ける
ComfyUI は生成が終わってもモデルをメモリに載せたままにする（次を速くするため）。手本・ポーズまで使うと約11GB抱えたままになった（2026-10-19）。
- **Claude が生成を頼まれたら、一続きの生成が終わったところで `dev/sd-studio/bin/start.sh free` を呼ぶ**（ComfyUI は止めない。次の1枚目だけ読み込み直しで20秒ほど遅くなる）
- 画面から使ったときは、ComfyUI-Manager の「モデルを下ろす（Unload Models）」ボタンで同じことができる

## gen.py の主なオプション
- `-m illust|photo` モデル切替
- `-n 4` 枚数（バッチ）
- `-s 832x1216` 解像度（SDXLは総画素100万前後が最適。1024x1024 / 832x1216 / 1216x832）
- `--seed 12345` 固定シード（同じ絵を再現したいとき）
- `--steps` `--cfg` `--sampler` `--scheduler`
- `--negative "..."` ネガティブ上書き
- `--raw` 品質タグを足さずプロンプトをそのまま使う
- `--tag card` 出力ファイル名の接頭辞

## モデルを増やす
`~/ComfyUI/models/checkpoints/` に `.safetensors` を置くだけ。LoRAは `models/loras/`。

## 注意
- 初回生成はモデルロードで数分かかる。2回目以降は約61秒/枚（illust既定 steps=20・約100万画素）
- **MPSではバッチで速くならない**。`-n 4` は4枚出るが所要時間もほぼ4倍（実測87s/枚のまま）
- `1536x1536` は落ちないが人物が二重化して構図が壊れる。SDXLは1024px級に収めること
- GUIとCLIは同じサーバを共有する。GUIで停止ボタンを押すと**CLIで走らせているジョブも止まる**（開いているだけなら影響なし）。止まった場合はCLIが exit 1 で明示的に失敗するので、黙って欠落することはない
- `--timeout`（既定900秒）は**キュー待ち時間も含む**。大量枚数（目安 `-n 15` 以上）や重い解像度では伸ばすこと。タイムアウトしても画像が壊れるわけではなく、サーバ側の生成は走り続ける（out/には来ない）
- **steps を変えると同じseedでも構図が変わる**。過去に記録したseedレシピは、当時のstepsも一緒に指定しないと再現しない
- ネガティブに nsfw 系を入れてあるが**完全ではない**（肩出し・露出寄りは残る）。素材として使う前に必ず目視すること
- 生成が失敗した場合も途中まで落ちた画像は `out/` に残る。**呼び出し側は out/ をglobせず exit code を見ること**（成功時のみ exit 0）
- SDXLでの `1024x1024` は 24GB なら余裕。Flux系を入れるならGGUF量子化版を使うこと（fp16は入らない）
- モデルのライセンスは各配布元に従う。商用利用の可否はモデルごとに違う
